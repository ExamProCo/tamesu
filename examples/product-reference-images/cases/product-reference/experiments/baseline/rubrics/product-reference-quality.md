# Product reference quality: rationale

The images will later serve as reference inputs for scanner experiments, so a usable image
shows one product clearly, from a known angle, and is safe to share.

Each dimension is **one** yes/no claim. An earlier draft bundled count, framing, viewpoint,
and background into a single "composition" dimension; a reviewer could not say an image was
fine except for its angle, and the report could not say which claim failed most. Split
dimensions fix both.

The camera angle is a hard requirement: scanner experiments need the front and one side
visible. A straight-on front view therefore fails `front-three-quarter-view`.

Failures carry a reason code from a fixed list so failure rates can be counted and the judge
and reviewer speak the same language. Every dimension also has `other`, for a failure the
list does not cover. A reviewer must explain `other` in the notes (the page and the import
both enforce this), and the report shows how often it is used. A high `other` count means
the rubric is missing a failure mode and should be revised before the next run.

There are no numeric scores. The overall verdict is computed: an image passes only if every
dimension passes.
